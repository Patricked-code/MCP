GWC PRE-CODE ACTION TASK FLOW — CANONICAL EXECUTION COMPANION
Revision: R4-CANDIDATE-ACTION-FLOW
Repository: Patricked-code/MCP
Target work branch: claude/ecstatic-edison-v1dyt1
Parent architecture plan: docs/gwc/PRECODE_EXECUTION_PLAN.txt

PURPOSE
Turn the approved canonical GWC plan into an explicit chronological queue of architecture and branch-local candidate work items that any authorized agent can resume, execute, evidence, checkpoint and hand off before live integration begins.

AUTHORITY BOUNDARY
- This file is an execution companion to PRECODE_EXECUTION_PLAN.txt.
- It is NOT Operational Memory.
- It is NOT the Governed Task Queue.
- Its GWC-PRE-* identifiers are architecture work-item identifiers, never TASK-* identifiers.
- It creates no GovernedTaskRecord, claim, lock, branch, permission, deployment or runtime mutation.
- Live authorities must be re-observed before any state-dependent claim.
- Existing completed evidence may satisfy a work item only after it is revalidated against the current exact branch head and the owning authority.
- Candidate work items never become runtime Governed Tasks automatically. Runtime Task reconciliation, if still required, occurs only in the later real-integration cycle after FINAL_PRECODE_VERSION_ACCEPTED.

ABSOLUTE RULE
NO CANDIDATE CODE MAY START BEFORE GWC_ARCHITECTURE_GATE_PASS; AFTER THAT GATE, BRANCH-LOCAL CANDIDATE CODE IS ALLOWED AND EXPECTED. NO LIVE INTEGRATION MAY START BEFORE FINAL_PRECODE_VERSION_ACCEPTED.
A documentation claim of COMPLETE is not sufficient by itself. Completion requires evidence references that can be re-read from the current branch/live authority.

STATUS VOCABULARY
PENDING            = not evaluated on the current exact branch head.
IN_PROGRESS        = actively being verified/completed.
PASS_WITH_EVIDENCE = completion proven by current evidence references.
BLOCKED            = cannot proceed because a declared dependency/gate is not satisfied.
CONFLICT           = authorities disagree; reconcile before proceeding.
STALE               = evidence expired or no longer bound to current head/state.
N/A                 = explicitly inapplicable with a documented reason.

GLOBAL EXECUTION LOOP
For every GWC-PRE-* work item:
1. OBSERVE current authorities.
2. RECONCILE with current branch/main/PR/task/session/locks/live state as applicable.
3. READ the existing artifact/code/test before changing anything.
4. EXECUTE only the bounded pre-code action.
5. VERIFY the exact completion condition.
6. RECORD evidence refs (file/ref/SHA/test output/reason code).
7. UPDATE checkpoint/projection only after verification.
8. MOVE to the next dependency-satisfied work item.
If a conflict appears: STOP that path, mark CONFLICT, reconcile, and continue only independent disjoint work.
