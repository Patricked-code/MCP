Pour certifier une livraison UTL, il faut encore relier des preuves distinctes, lorsqu'elles sont requises : `continuity_id`, `parent_task_or_work_ref`, `utl_ref` (non formel dans le MCP historique), `branch_head_sha`, `pr_ci_run_id`, `merge_commit_sha`, `main_ci_run_id`, `deploy_workflow_run_id`, `deploy_job_id`, `requested_sha`, `runtime_revision`, vérifications de santé, tests métier de bout en bout et checkpoint. **Ne jamais déduire l'existence d'une Task runtime ni un déploiement réussi d'un seul `merge_commit_sha`.**

La liste est un **snapshot historique** au SHA `05dbb66ed81aa4e7443655c89d10c0c390ff0f10` ; toute PR fusionnée après sa génération doit faire l'objet d'une mise à jour vérifiée plutôt que d'être ajoutée par supposition.
